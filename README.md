# 🍓 Celeste Smart Clipper (Celeste 智能回放剪辑脚本)

> [!IMPORTANT]
> 🤖 **AI 含量极高**
> 本项目代码由 AI 深度辅助编写。代码虽然能跑，但可能充满未知的玄学逻辑，主要供大家娱乐和参考。

配合 [VidCutter](https://gamebanana.com/mods/580133) 模组的输出日志，自动识别游戏内死亡/重生事件，一键从 OBS 回放缓存中精准截取通过片段。

默认只保留 **「复活动画结束 → 按下剪辑键」** 的画面，死亡前的等待、死亡动画和复活过场都不会混进成片。

告别海量素材堆积，告别手动剪辑痛苦！

## ✨ 主要功能

* **智能剪辑**：自动根据死亡/重生时间点，从 OBS 缓存中截取通关片段。
* **纯净片头**：默认剔除死亡前缓冲与死亡/复活动画，从复活结束开始保留。
* **精确起点**：默认重新编码，帧级精准裁切，片头不会因关键帧对齐而多出复活画面。
* **自动命名**：支持文件名自动包含地图名、房间名（需 VidCutter 支持）。
* **自动去重**：若新片段包含旧片段，自动清理冗余文件。
* **按键反馈**：支持操作提示音，盲操更安心。

## 📦 安装与配置

### 1. 前置要求

* **Celeste 游戏**：需安装 [**VidCutter**](https://gamebanana.com/mods/580133) Mod（用于生成日志）。
* [**OBS Studio**](https://obsproject.com/)：需开启 **回放缓存** (Replay Buffer)，建议设置时长 ≥ 300 秒。

### 2. 脚本安装

1. 下载本仓库的 `CelesteSmartClipper.py`。
2. 下载 Releases 中的 `Python_Environment.zip` 并解压到一个固定位置（路径尽量无中文）。
   * 也可以选择自行搭建环境，注意 OBS 不支持版本过高的 Python。
3. **OBS 设置** → **工具** → **脚本** → **Python 设置**：
   * 选择刚才解压的 Python 环境文件夹。
4. 回到 **脚本** 标签页，点击 `+` 号加载 `CelesteSmartClipper.py`。

### 3. 参数设置

* **Celeste 游戏根目录**：填写你的游戏安装路径。
* **OBS 热键绑定**：去 **设置 → 热键** 搜索 `Celeste`，绑定以下三个关键按键：
  * `Celeste: 1. 标记本轮起点`
  * `Celeste: 2. 追溯上一轮起点`
  * `Celeste: 3. 剪辑通过片段`

* **剪辑范围设置**（首次加载后确认以下两项已勾选）：

| 设置项 | 默认值 | 说明 |
| :--- | :--- | :--- |
| **只保留复活结束后的片段** | ✅ 开启 | 片段从复活动画结束后开始，剔除死亡前缓冲与死亡/复活过场。开启时「剪辑缓冲时间」自动失效。 |
| **死亡后跳过时间 (秒)** | `1.0` | 从死亡标记点向后跳过多久开始保留。Celeste 死亡+复活过场通常约 1~1.5 秒，可按章节微调。 |
| **精确起点（重新编码）** | ✅ 开启 | 帧级精确裁切，片头不会多出画面；代价是剪辑速度稍慢。 |
| **剪辑缓冲时间 (秒)** | `1.0` | 仅在**关闭**「只保留复活结束后的片段」时生效，表示在标记点前额外保留的秒数。 |

## 🎮 使用流程

### 1. ⚔️ 受苦 (Play)

正常游玩，反复尝试直到通过当前房间。

### 2. 📍 标记 (Mark)

**在本面通过后、切版前**（或刚切入下一面画面稳定时），按下 **[标记键]**。

> 脚本会锁定“最近一次死亡时间”。实际片段起点 = 该死亡时间 + 「死亡后跳过时间」。

### 3. 🎬 剪辑 (Clip)

在下一面站稳后，按下 **[剪辑键]**。

> 脚本会自动导出 **从复活动画结束到按下剪辑键那一刻** 的纯净通关视频，死亡前画面不会再被带进来。

## 🚑 急救指南 (FAQ)

| 场景/症状 | 解决方案 | 原理 |
| :--- | :--- | :--- |
| **手滑了**：通过后忘了按标记，切图后不小心又死了一次 | 复活后按 **[追溯]** → 再按 **[剪辑]** | 放弃最近一次死亡，回滚到上一次死亡点作为起点 |
| **被坑了**：复活点只有死过一次后才能站立 | 复活稳定后按 **[追溯]** | 同上 |
| **要留档**：捡到钥匙/超唐操作后死亡，想保留这段录像 | 复活后按 **[追溯]** → 再按 **[剪辑]** | 将“捡到道具前的复活点”设为视频起点；该点之后直到剪辑键的画面都会保留 |
| **想连死亡前画面一起留**：唐死魅力时刻/死亡前的操作也想看到 | 关闭「只保留复活结束后的片段」后再剪辑 | 回到旧行为，按「剪辑缓冲时间」向前多保留一段 |
| **片头还残留复活黑屏/渐显** | 把「死亡后跳过时间」调大 `0.1~0.5` 秒 | 复活动画比预期长，起点需要再往后挪 |
| **片头把已经能操作的画面也剪掉了** | 把「死亡后跳过时间」调小 | 起点跳过头了 |
| **剪辑速度变慢** | 关闭「精确起点（重新编码）」 | 回到流复制快速剪切，但片头可能因关键帧对齐而提前一点 |

> **☠️ 绝望时刻**：如果你在标记前死了 3 次以上……脚本救不了你了，请手动导出 OBS 完整回放缓存自行剪辑。

## ⚠️ 注意事项

1. **不要把脚本放进游戏 Mods 文件夹**：这是一个 OBS 脚本，不是游戏 Mod。
2. **单个视频时长上限**：受限于 OBS 回放缓存的设置时长（建议设大一点，如 300 秒+）。
3. **关键帧机制**：默认开启「精确起点（重新编码）」时，起点是帧级精确的，不会多出死亡/复活画面。
   * 关闭该选项后会使用 FFmpeg 流复制，切割点必须依附于关键帧，片头可能比目标时间点提前几秒（取决于 OBS 的关键帧间隔）。
   * 若坚持使用流复制又想更精准，可在 OBS 输出设置中将“关键帧间隔”设为 2 秒或 1 秒。
4. **重编码会稍慢**：这是精确起点的代价，不是卡住了。追求导出速度可关闭「精确起点（重新编码）」。
5. **不同章节的死亡+复活过场时长可能不同**：如果某个章节片头不准，单独微调「死亡后跳过时间」即可。
